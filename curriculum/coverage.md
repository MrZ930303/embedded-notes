## 八阶段的范围与阶段证据

01—09 已有实际发布证据，06—09 的本地与发布范围见[阶段02证据](stage02-evidence.md)；10—11已有父任务确认的发布证据；本批 **12—14** 为本地候选，见[阶段03本地证据](stage03-evidence.md)，后续 **15—32** 仍待建设。定时器与非阻塞周期控制在 **10**，不跳过 C、缓冲区和启动先修。阶段01已有[本地范围证据汇总](stage01-evidence.md)，浏览器与独立审查结果分别见本批交付验收记录，远端发布另验；八个阶段均未宣称整体完成。

### 阶段 01 · C、GPIO 与有界状态（01—05）

01 从电路、电压和观测推导一次可靠按下；02 推导输出通路、条件化限流和同时预算，消费已过滤的人工事件，将业务期望映射为固定接线下的命令。01—05 已发布；完整阶段验收和硬件状态分开。

03 要覆盖 RW / RO / W1C 语义、掩码和 RMW 交错，提供主机 C 掩码测试与两个错误 RMW 反例，不声称解决全部并发。04 用内存格模型解释对象、指针、长度、生命周期、结构体、字节序与整数转换；未定义行为不能演示成固定结果；检查零、最大值和边界，解释 size_t、const、volatile 的适用限制。05 提供单上下文有界 FIFO 模块和重放种子，验证空、满、回绕、非法输入与所有权，不宣称线程安全。

阶段证据：输入事件、输出意图与电平映射、C 边界检查、FIFO 重放各自可复现，失败输入有明确结果；硬件另验。

### 阶段 02 · 构建与启动（06—09）

06 用多文件主机构建说明预处理、编译、链接、ELF / bin / map / 符号与 build ID / 版本，查 GNU / Arm 官方资料。07 用明确虚构的镜像与 RAM 执行模型解释复位向量、初始 SP、data 复制、BSS 清零与 main，覆盖非法入口与越界，核对 CMSIS / 内核和选定内存图。

08 用 map 核算静态 RAM、栈、堆与生命周期；检查深调用、递归风险和水位线的限制，采用 ABI / 编译器证据。09 推导时钟源、PLL、总线到 tick 的链路及误差、失败和 UART / 定时器算术；既有 F407 计算器保留明确型号范围，实际配置仍查选定 RCC / Flash 手册。

阶段证据：新检出可复现构建，能识别产物版本、解释内存占用与启动步骤，并区分计算时钟和测量时钟。

### 阶段 03 · 时间、外设与恢复（10—14）

10 解释定时器、PWM、非阻塞期限、计数回绕、迟服务与 0 / 100% 边界，先声明计数模式。11 将 UART 分片与粘连字节转成有界消息，覆盖长度、校验、超时和重新同步。12 分清 I2C 地址与事务、SPI CS 与模式，覆盖 NACK、忙和超时；以 NXP 规范、传感器与 MCU 手册交叉核对，可拆两页但只计一个单元。

13 先轮询后 DMA，解释 ADC 量化、参考电压、采样时间、源阻抗和混叠。14 用假后端验证有限错误、超时、恢复与有界重试；断开设备时命令终端仍可响应。

阶段证据：协议输入可重放，错误码、单位、范围和超时可检查；传感器失败不让终端无限等待。

### 阶段 04 · 中断、DMA 与吞吐（15—17）

15 区分异常 pending / active / 抢占 / 屏蔽与共享 RMW；明确实际优先级位数和分组，并限制 ISR 工作量。16 解释 DMA 所有权、乒乓缓冲与消费者迟到，分别处理 RAM 可访问性和有缓存型号；AN4031 的 F2 / F4 / F7 范围与 AN4839 的具体缓存范围不能泛化。

17 用速率、开销、抖动、缓冲与序号解释吞吐及过载，说明何时丢失数据、如何报告并恢复。

阶段证据：在声明的负载预算下检出序号缺口和迟消费，报告过载行为，不以动画流畅替代测量。

### 阶段 05 · FreeRTOS（18—21）

18 用官方主机移植或明确选择的目标运行时验证任务、状态、优先级、周期和 tick；JavaScript 不等于 RTOS。19 区分队列与通知、复制与指针、所有权、满、超时及 FromISR。20 区分互斥与信号量、优先级继承与死锁，以等待图和三个任务验证锁顺序。

21 核对 ISR 优先级与 yield、任务 PSP 与 MSP 的资源区别，运行三任务负载终端，并连接 EasyLogger 的使用边界。

阶段证据：调度、通信、等待关系和资源峰值可观察，队列满和超时有结果；模拟状态与真实运行时分开记载。

### 阶段 06 · 调试与测试（22—24）

22 覆盖调试连接、复位、断点、观察点、ELF 符号和 build ID，以假内存中的错误写入形成诊断练习；Keil / SEGGER 是可选案例，不要求安装。23 从原始故障快照出发，说明栈帧置信条件、符号匹配、根因、修复与回归，连接 HardFault / EasyLogger 的明确适用范围。

24 区分单元、集成与 HIL，使用故障注入、重放种子、可选 sanitizer 和已知提交的 bisect；至少包含内存、并发、协议三类错误。

阶段证据：每个故障都有触发、现场、根因和回归，不能只保存“PASS”或把主机桩当成 HIL。

### 阶段 07 · Flash、信任与升级（25—28）

25 查实际 Flash 擦写粒度、规则和寿命，解释元数据、向量和启动跳转，检出重叠与非法镜像。26 建立 CRC / 哈希 / 签名 / 版本的威胁模型，采用可信加密库与公开测试密钥，不自创密码算法。

27 在每个持久化边界注入断电，分别验收安装恢复、试运行确认、回滚和独立救援；区分允许的旧版与被策略禁止的安全降级。28 先串口后可选网络适配器，验证有界块传输、重复、幂等、断线、全镜像验证、提交与确认。

阶段证据：篡改、断电和传输重试可重放，双槽不自动等于回滚、外部暂存不自动保留旧版、双 Bank 不自动等于 A/B；单槽方案保留独立救援条件。

### 阶段 08 · 系统交付（29—32）

29 建立领域、协议、驱动、BSP 的契约，两个假后端和契约测试不能写成两块实板验证。30 用两个版本化记录保存配置，注入持久化断电，并验证故障状态、看门狗健康条件与复位风暴。

31 核算状态驻留时间、唤醒、时钟超时和长时负载资源；模拟能耗不是实测功耗。32 从干净检出复现终端，串起需求→测试→构建版本、许可、产物、诊断、升级和恢复指南。

阶段证据：另一位工程师可复现构建与故障，按文档识别版本、升级和恢复，明确资源范围、取舍与未解决风险。
