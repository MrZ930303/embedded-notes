# MCU OTA：从分区到回滚 {#overview}

“固件下载成功”只是第一步。真正要设计的是：新固件放在哪、何时替换旧固件，以及断电或新程序失效后，设备还能启动什么。

面向 STM32 / GD32 等 MCU。资料核对：2026-10-17。交互为本地教学模型，不执行下载、刷写或设备操作；所有容量为估算，未做硬件验证。

## OTA 不是一种分区方式 {#layers}

OTA 严格指无线更新；有线或网关链路可归入更广义的固件更新 / DFU。它们可以共用下面的存储与安装机制。先把通信链路、镜像存储和启动策略拆开。 [[2]](#src2)

TRANSPORT

怎么拿到固件

Wi-Fi、蜂窝、BLE、以太网可以传 OTA 包；UART、USB、CAN 也可以承载本地或网关转发升级。它们不决定底层怎么替换固件。

STORAGE

固件暂存在哪里

覆盖当前应用、内部 Flash 暂存、外部 SPI NOR 暂存，或直接保留两个可运行槽。存储位置决定容量和安装路径。

BOOT POLICY

失败后启动谁

Bootloader 验证、选择、安装镜像。试运行确认与恢复策略决定：安装可续做、退回旧版，还是只能进入救援模式。

三个能力，分别验收：下载可续传 ≠ 安装断电可恢复 ≠ 新版本失败可回滚。前两项解决“没装完”，第三项解决“装完了但不好用”。 [[1]](#src1) [[5]](#src5)

## 点选架构，把一次升级走完 {#lab}

常见路径可概括为：单槽直接覆盖、双区暂存后复制、双槽交换、A/B 直接执行。外部 Flash 是暂存位置的选择；恢复镜像是可叠加的救援机制。下方是典型设计的教学模型。

实现参考：[MCUboot 策略 [1]](#src1) · [ST 单 / 双槽配置 [3]](#src3) · [外部次槽 [7]](#src7) · [测试与确认 [8]](#src8)

单槽覆盖

核心收益内部 Flash 占用少

代价擦除旧应用后，没有完整旧版

失败后可靠 Bootloader / ROM 通道重新刷入

适用可接触设备、救援链路有保障

暂存后复制 · 内部

核心收益下载、验签完成后再破坏旧版

代价通常需要两份镜像容量

失败后可从完整暂存镜像重做安装；不会自动保留旧版

适用容量够、重点是安装可恢复

暂存后复制 · 外部

核心收益节省内部 Flash

代价增加器件、驱动与外部存储故障面

失败后同上；外部只有新版时无旧版可退

适用有 SPI NOR、内部 Flash 紧张

交换式双槽 · Swap

核心收益固定执行地址，保留旧版用于回退

代价擦写时间、寿命与事务状态更复杂

失败后按状态续做交换；未确认新版可反向交换

适用需要试运行回滚、移植条件满足

A/B 直接执行

核心收益下载到非活动槽；切换无需全量搬运

代价执行地址、重映射与安全切换必须解决

失败后仍有效且未被覆盖的旧槽可作为回退目标

适用硬件 / 链接布局支持且容量足够

独立恢复镜像

核心收益正常应用损坏时仍有救援入口

代价额外保护区、长期维护恢复路径

失败后进入最小恢复系统，重新获取应用

适用长期部署设备；可与其他方案叠加

单槽覆盖：接收固件时直接擦写唯一应用槽。Bootloader / 恢复通道必须独立可用；旧应用一旦被覆盖，就不能靠这个槽退回。

假设：Bootloader 保持完整，且能在应用无效时通过可靠链路重新刷入。此模型不承诺原地写入断电后自动续传；整包验签通常在写完后完成，启动前必须验证。

1. V1 正常运行。开始升级前进入可独立接收固件的更新环境。
2. 边接收边擦写应用槽；此时旧固件可能已被破坏，未完成镜像不可启动。
3. 验证已写入的完整目标镜像；验签失败则留在恢复路径，不能启动它。
4. 把验证通过的 V2 标记为可启动；没有完整旧版副本。
5. V2 首次运行。可做健康检查，但检查失败并不凭空产生旧镜像。
6. V2 成为正式版本。若故障，仍需重新刷入可用镜像。

内部暂存复制：先把 V2 下载到内部暂存区并验证，再复制到固定执行槽。暂存 V2 让安装可以恢复，但旧 V1 会在复制中被覆盖。

假设：暂存区保留完整且验证通过的 V2；Bootloader 有可靠的安装状态和可重复执行且不破坏结果的复制 / 重做策略。这里只有新版暂存，不额外保留完整 V1，因此不承诺旧版回滚。

1. 执行槽运行 V1，暂存区为空。
2. 下载到暂存区，V1 保持完整；是否后台运行仍取决于 Flash 限制。
3. 校验完整 V2、签名、机型和版本策略；不合格则不开始覆盖。
4. Bootloader 把 V2 复制到执行槽。断电后可依据状态续做或从头重做。
5. 运行 V2；V1 已被覆盖。失败时可重装同一 V2 或进入恢复流程。
6. 提交 V2。暂存区何时清理取决于恢复策略，不能在安装完成前清掉唯一有效来源。

外部暂存复制：在 SPI NOR 等外部存储里暂存 V2，再写入内部应用槽。内部只需一个执行槽，但外部一个新版副本不会自动保留旧版。

假设：Bootloader 能可靠访问外部存储；V2 在安装完成前持续可读；安装日志和复制过程可恢复。外部内容属于不可信输入，启动 / 安装前仍需做适当验证。

1. 内部运行 V1；外部暂存区可用。
2. 把 V2 下载到外部 Flash。内部 V1 不被修改。
3. 验证外部 V2 的完整性、签名和适用性；必要时安装前复验。
4. 从外部逐块复制 V2 到内部。可从完整暂存源续做 / 重做，但 V1 逐步消失。
5. V2 试运行；没有额外 V1 备份时，不能回滚到上一版。
6. 提交 V2，按策略处理外部暂存副本。外部器件故障也要纳入恢复设计。

交换式双槽：V2 先放次槽，再通过可恢复的交换流程进入固定执行槽；V1 被留到次槽。启用试运行 / 回退策略后，未确认的 V2 可换回 V1。

假设：选择支持回退的 swap 算法并启用相应状态处理；匹配扇区几何、工作区和持久化日志；未确认重启触发回退。不是所有“双槽”配置都满足这些条件。

1. 主槽运行 V1，次槽等待新镜像。
2. V2 下载到次槽，主槽 V1 不变。
3. 验证 V2；持久化测试升级请求。
4. 逐块交换，主槽最终为 V2、次槽保留 V1。中途两槽可能都是混合状态，必须按日志恢复。
5. V2 以“未确认”状态运行。关键自检成功后才允许确认；看门狗负责把死机转为复位。
6. 确认 V2，结束本次自动回退窗口。下次升级可能覆盖保存的 V1。

A/B 直接执行：A、B 都能成为执行槽。下载到非活动槽，验证后切换启动选择；不搬运整个镜像。旧槽保持完整，可供未确认升级回退。

假设：两个地址都能正确执行（匹配链接地址 / 重定位 / 硬件重映射）；Bootloader 支持可靠启动选择、试运行回退和冗余状态记录；旧槽未被覆盖且仍符合安全版本策略。

1. 从槽 A 运行 V1，槽 B 非活动。
2. 把 V2 下载到槽 B。不能覆盖仍用于回退的活动镜像。
3. 检查 V2 适用性和签名，记录待测试槽。
4. 可靠地提交“下一次从 B 启动”；不需要整镜像复制。具体可用性依赖启动元数据设计。
5. 从 B 运行未确认 V2；若失败并复位，Bootloader 可选择 A 中的 V1。
6. 确认 B 中 V2。A 可在后续升级被重新使用，所以历史版本不会无限保留。

独立恢复镜像：保护一份最小恢复程序，正常应用不可用时由它重新下载 / 安装固件。它是救援底座，可以与其他方案组合，不等于上一版业务固件。

此处示例：一个普通应用槽 + 受保护的恢复镜像；由恢复环境覆盖应用。恢复镜像仍需可信启动、可用通信和独立参数，不保证离线恢复完整业务。

1. V1 正常工作，恢复镜像 R 独立保留。
2. 恢复环境接收 V2 并覆盖普通应用槽；R 保持完整。
3. 验证普通槽的完整 V2；失败则继续留在 R。
4. 选择有效 V2 进入应用；R 不变。
5. 若 V2 失败，可靠的启动失败判定可把设备带回 R，而不是 V1。
6. 确认 V2。R 继续作为救援入口，恢复服务仍需长期维护。

断电检查：准备阶段 V1 完整；下载阶段，单槽可能破坏 V1，恢复方案保留 R，其他方案保留 V1。验证后仍要重验镜像和可信状态；安装时暂存复制只能恢复安装，Swap 依据交换日志恢复一致状态，A/B 需要处理启动元数据撕裂。试运行未确认复位，在本模型的回退策略下 Swap / A/B 退回 V1；恢复方案进入 R；无旧版的方案只能重装或救援。确认后自动回退窗口结束，确认记录本身也需可靠提交。

新版失败检查：看门狗或外部机制复位后，Swap 反向交换，A/B 选择仍完整且允许执行的 A；R 用于重新刷写而不是回滚 V1。其他方案没有完整 V1，重复安装相同缺陷 V2 不能解决软件故障。参数格式不兼容仍可使业务恢复失败。

双槽不等于可回滚，外部暂存不等于保留旧版，双 Bank 不等于 A/B；单槽必须保留独立且可靠的救援入口。

## 先算下限，再画真实分区表 {#capacity}

统一以 KiB（1 KiB = 1024 字节）输入，镜像取未来最大值而非当前编译大小。

默认：内部 Flash 1024 KiB、最大载荷 320、Bootloader 64、数据 32、擦除粒度 8、每槽头 / 签名 / 尾部 8、状态 / 冗余记录 8、Swap 工作区 16、恢复镜像 96。

内部需求 = 分别对齐后的固定区 + 内部槽数 × 对齐后的单槽 + 所选额外区。单槽 = 向上对齐（载荷 + 每槽格式开销）。单槽覆盖、外部暂存、恢复镜像使用一个内部槽；内部暂存、Swap、A/B 使用两个内部槽。Swap 加工作区，恢复方案加已包含自身格式开销的恢复镜像区；外部暂存另需一个外部槽。

默认结果：单槽 / 外部暂存内部 432 KiB，内部暂存 / A/B 760 KiB，Swap 776 KiB，恢复镜像 528 KiB；外部暂存另外需要至少 328 KiB。容量不足显示缺口；空值、负值、非有限值与算术溢出拒绝估算。

所有输入是规划值，不是 SDK 默认值。Swap 工作区覆盖所选算法 scratch / 额外扇区。外部擦除粒度可能不同，本例不单独建模。

不是可直接烧录的分区表：真实芯片还可能存在非均匀扇区、Bank 边界、保护粒度、保留地址、读写互斥、镜像工具槽限制、最大 trailer 与增长空间。算术够用不保证可实现。

## STM32 / GD32 + Keil + FreeRTOS 怎么选 {#practice}

START HERE

先确定可靠性目标

无人值守设备，优先评估“保留旧版 + 试运行确认”的 Swap 或 A/B；容量不足时，可评估外部暂存，并明确这是恢复安装还是完整回滚。

CHECK THE CHIP

再看具体料号

核对 Flash 大小、扇区地图、单 / 双 Bank、读写并行、Bank swap / 地址映射、写入粒度与保护能力。STM32 的一个系列经验不能直接套到所有 GD32 或其他 STM32。

IMPLEMENT CAREFULLY

最后落到工程

Keil scatter 文件、向量表、镜像头、签名脚本必须和 Bootloader 布局一致。FreeRTOS 负责任务调度，不会自动提供原子升级或回滚。

Bootloader 和应用的边界先定清保护 Bootloader、信任根及恢复入口。它自己的升级应单独设计冗余和恢复，不能默认使用普通应用升级流程。应用下载可由任务完成；重启后的安装可由 Bootloader 完成。

别把改 VTOR 当成“任意地址运行”VTOR 只选择向量表。绝对地址引用仍然受链接布局影响；A/B 需要分别链接对应地址、可重定位镜像，或经过验证的硬件重映射。跳转时还要按架构处理堆栈、中断、SysTick、缓存与外设状态。

Flash 擦写影响系统实时性核对同 Bank 取指 / 读取是否停顿、驱动是否需要 RAM 执行、中断服务与看门狗是否受影响。双 Bank 不等于无需检查读写并行限制。 [[4]](#src4)

把“第一次启动”作为一个事务持久化待测试标记 → 启动新版 → 检查关键服务 / 外设 / 通信 → 明确确认。新版死循环不能靠自己发起回滚，要有看门狗或其他复位机制和启动失败判定。

每一个擦写边界都做断电测试覆盖下载、校验、擦除、复制 / 交换、启动选择标记、确认记录与回滚过程；核对日志损坏、低电压、镜像尺寸边界、外部 Flash 故障与连续升级。此页面不代替这些验证。

### 安全底线：CRC 不是可信来源证明 {#image-trust}

CRC 可发现偶发传输错误；Hash 可检查内容是否匹配可信摘要；签名验证用于确认发布方并检测篡改。保护公钥 / 信任根及验证链路，并在真正启动或安装前按威胁模型复验。TLS 有帮助，但不能替代镜像签名。 [[9]](#src9)

防降级策略与故障回滚需要共同设计：安全计数器、允许回退的版本范围和“何时提交不可逆版本下限”必须一致。不要在新固件尚未验证可用时，先让旧版被安全策略永久拒绝。 [[5]](#src5)

### 程序能回滚，参数和数据库也能吗？ {#data-compatibility}

新版若把配置改成旧版不认识的格式，退回旧固件仍可能无法工作。为参数区单独设计版本标记、兼容读取、事务写入或双份记录。必要时延迟破坏性迁移，保留旧数据快照，并测试“新版运行一段时间后回滚”。

### 差分、压缩、加密：它们不是新的槽位方案 {#package-formats}

这些是包格式和处理方式，可以叠加到暂存、Swap 或 A/B 上。差分节省传输量，但需要准确基线，并计入补丁、重建输出和断电恢复空间。压缩需要解压后空间；加密解决机密性，不独自证明镜像可信。最后要验证完整目标镜像，不能拿很小的补丁尺寸替代应用槽大小。 [[10]](#src10)

### 几个容易混用的术语 {#terminology}

双槽：两块镜像逻辑存储区域，可以位于同一个 Bank 或外部 Flash。

双 Bank：硬件 Flash 组织方式，具体读写并行、地址映射能力由料号决定。

Swap：这里指软件交换两份镜像，和某些芯片的硬件 Bank swap 不是同一动作。

恢复镜像：提供重新安装能力的已知可用程序，不一定是上一版完整业务固件。

RAM-load：从存储加载到 RAM 执行的另一类实现；需要足够 RAM 和对应启动支持，本页不作为主要对比项。
