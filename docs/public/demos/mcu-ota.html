MCU OTA
从分区到回滚

“固件下载成功”只是第一步。真正要设计的是：新固件放在哪、何时替换旧固件，以及断电或新程序失效后，设备还能启动什么。

面向 STM32 / GD32 等 MCU资料核对 · 2026-10-17离线可用 · 无外部依赖架构说明 · 未做硬件验证
先分清三件事交互看方案估算容量落地检查官方资料
01 /

OTA 不是一种分区方式

OTA 严格指无线更新；有线或网关链路可归入更广义的固件更新 / DFU。它们可以共用下面的存储与安装机制。先把通信链路、镜像存储和启动策略拆开。 [2]

TRANSPORT

怎么拿到固件

Wi-Fi、蜂窝、BLE、以太网可以传 OTA 包；UART、USB、CAN 也可以承载本地或网关转发升级。它们不决定底层怎么替换固件。

STORAGE

固件暂存在哪里

覆盖当前应用、内部 Flash 暂存、外部 SPI NOR 暂存，或直接保留两个可运行槽。存储位置决定容量和安装路径。

BOOT POLICY

失败后启动谁

Bootloader 验证、选择、安装镜像。试运行确认与恢复策略决定：安装可续做、退回旧版，还是只能进入救援模式。

三个能力，分别验收：下载可续传 ≠ 安装断电可恢复 ≠ 新版本失败可回滚。前两项解决“没装完”，第三项解决“装完了但不好用”。 [1] [5]

04 /

STM32 / GD32 + Keil + FreeRTOS 怎么选

START HERE

先确定可靠性目标

无人值守设备，优先评估“保留旧版 + 试运行确认”的 Swap 或 A/B；容量不足时，可评估外部暂存，并明确这是恢复安装还是完整回滚。

CHECK THE CHIP

再看具体料号

核对 Flash 大小、扇区地图、单 / 双 Bank、读写并行、Bank swap / 地址映射、写入粒度与保护能力。STM32 的一个系列经验不能直接套到所有 GD32 或其他 STM32。

IMPLEMENT CAREFULLY

最后落到工程

Keil scatter 文件、向量表、镜像头、签名脚本必须和 Bootloader 布局一致。FreeRTOS 负责任务调度，不会自动提供原子升级或回滚。

Bootloader 和应用的边界先定清保护 Bootloader、信任根及恢复入口。它自己的升级应单独设计冗余和恢复，不能默认使用普通应用升级流程。应用下载可由任务完成；重启后的安装可由 Bootloader 完成。

别把改 VTOR 当成“任意地址运行”VTOR 只选择向量表。绝对地址引用仍然受链接布局影响；A/B 需要分别链接对应地址、可重定位镜像，或经过验证的硬件重映射。跳转时还要按架构处理堆栈、中断、SysTick、缓存与外设状态。

Flash 擦写影响系统实时性核对同 Bank 取指 / 读取是否停顿、驱动是否需要 RAM 执行、中断服务与看门狗是否受影响。双 Bank 不等于无需检查读写并行限制。 [4]

把“第一次启动”作为一个事务持久化待测试标记 → 启动新版 → 检查关键服务 / 外设 / 通信 → 明确确认。新版死循环不能靠自己发起回滚，要有看门狗或其他复位机制和启动失败判定。

每一个擦写边界都做断电测试覆盖下载、校验、擦除、复制 / 交换、启动选择标记、确认记录与回滚过程；核对日志损坏、低电压、镜像尺寸边界、外部 Flash 故障与连续升级。此页面不代替这些验证。

安全底线：CRC 不是可信来源证明

CRC 可发现偶发传输错误；Hash 可检查内容是否匹配可信摘要；签名验证用于确认发布方并检测篡改。保护公钥 / 信任根及验证链路，并在真正启动或安装前按威胁模型复验。TLS 有帮助，但不能替代镜像签名。 [9]

防降级策略与故障回滚需要共同设计：安全计数器、允许回退的版本范围和“何时提交不可逆版本下限”必须一致。不要在新固件尚未验证可用时，先让旧版被安全策略永久拒绝。 [5]

程序能回滚，参数和数据库也能吗？

新版若把配置改成旧版不认识的格式，退回旧固件仍可能无法工作。为参数区单独设计版本标记、兼容读取、事务写入或双份记录。必要时延迟破坏性迁移，保留旧数据快照，并测试“新版运行一段时间后回滚”。

差分、压缩、加密：它们不是新的槽位方案

这些是包格式和处理方式，可以叠加到暂存、Swap 或 A/B 上。差分节省传输量，但需要准确基线，并计入补丁、重建输出和断电恢复空间。压缩需要解压后空间；加密解决机密性，不独自证明镜像可信。最后要验证完整目标镜像，不能拿很小的补丁尺寸替代应用槽大小。 [10]

几个容易混用的术语
  • 双槽：两块镜像逻辑存储区域，可以位于同一个 Bank 或外部 Flash。
  • 双 Bank：硬件 Flash 组织方式，具体读写并行、地址映射能力由料号决定。
  • Swap：这里指软件交换两份镜像，和某些芯片的硬件 Bank swap 不是同一动作。
  • 恢复镜像：提供重新安装能力的已知可用程序，不一定是上一版完整业务固件。
  • RAM-load：从存储加载到 RAM 执行的另一类实现；需要足够 RAM 和对应启动支持，本页不作为主要对比项。
