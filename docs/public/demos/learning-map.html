怎么使用这张地图

先沿主线建立能力，再把笔记当作随时可查的工具。全程建议逐步完善同一个“可升级的数据采集终端”：能读传感器只是开始，还要知道何时会丢数据、怎样定位错误，以及更新失败怎样恢复。

主线围绕通用原理、驱动设计和调试方法展开，不绑定开发板或固定引脚。交互模型与独立练习可先在浏览器、主机测试或桩驱动中完成；后续硬件验证可自主选择目标。STM32/GD32、Cortex-M、FreeRTOS 以及 Keil/J-Link 只作为明确适用范围的实现或工具案例。上板时必须核对真实芯片的数据手册、参考手册与板级资料，寄存器配置不能跨 MCU 直接套用。嵌入式 Linux 是后续独立方向，不要求同时铺开。高级工程能力以需求、实现、测量、故障复盘和可维护交付证明，课程完成量不能保证岗位或收入。

核心知识

贯穿项目
设计按键输入与 LED 控制的驱动接口，并在主机上测试状态逻辑和定长缓冲区；硬件可后续接入。
验收证据
解释按下前后的引脚状态；检查空、满、回绕和越界输入；能说明错误来自电路、配置还是程序。接入硬件时先做安全低压实验。
第一课：按下按钮，为什么读到 0？

本阶段从一个能解释清楚的输入事件开始。首章有两个检查点：先独立推导上下拉、电平与采样事件，再进阶到可编译 C、启动和时间契约。GPIO 输出、LED 限流、完整 C 基础与缓冲区课程仍在建设中；本章通过不等于完成本阶段。实物测量留到选择具体目标后另行记录，模型和主机测试不等于上板验证。

02 /

启动与内存：解释程序怎样开始运行

先修
01：电路与 C。
核心知识
学习编译链接、启动文件、向量表、寄存器、Flash/RAM、栈堆和时钟树。
贯穿项目
从复位运行到串口自检，输出明确的固件版本。
验收证据
新检出工程能复现构建；用 map 文件解释静态占用；单步复位至 main；测得的时钟输出与计算相符。
MCU 堆栈原理与监测 · MCU 晶振与主频 · Cortex-M CPU 核心寄存器

现有堆栈、PLL 和 Cortex-M 寄存器笔记为本阶段提供实现案例，也支撑后面的任务栈预算、外设速率、异常现场与采样预算；具体配置以各笔记声明的芯片和内核范围为准。

03 /

外设与协议：从调通到会处理异常

先修
02：启动与内存。
核心知识
学习 GPIO、定时器、UART、I²C/SPI、ADC、驱动接口、状态机与超时；HAL/LL 作为特定芯片生态的实现案例。
贯穿项目
采集传感器并通过串口命令查询。
验收证据
抓包与协议时序对应；断开传感器后系统仍可响应；非法、截断、超长命令有确定结果，接口写明单位、范围与错误码。
GPIO 按键首课；协议与超时原创小课建设中。

先把“读到了什么”变成有单位、范围与错误含义的接口，再增加外设数量。不同芯片与库的初始化不能直接照搬。

04 /

中断与 DMA：让数据在负载下仍然可信

先修
03：外设与协议。
核心知识
学习中断控制、共享数据、原子性、DMA、双缓冲、环形缓冲与过载处理；NVIC 作为 Cortex-M 的实现案例。
贯穿项目
定时采样、DMA 搬运、串口连续输出。
验收证据
先声明采样率、允许抖动及吞吐预算，再测量；用序号检出丢帧；压力下满足预算或明确报告过载。不能把 volatile 当作并发同步。
Cortex-M 寄存器与异常入口；DMA 原创实验建设中。

ST DMA 文档的适用范围是具体系列；每个实验都须对照选定型号手册，不能把一个系列的 DMA 行为推广到全部芯片。

05 /

任务与并发：清楚谁拥有数据、谁在等待谁

先修
04：中断与 DMA。
核心知识
学习调度、数据所有权、任务间通信、互斥、优先级反转、中断与任务协作、超时和栈预算；用 FreeRTOS 的任务通知、队列与 ISR API 对照具体实现。
贯穿项目
采集、协议与存储任务协作。
验收证据
画出数据所有权和等待关系；复现并修复竞争；记录响应时间、队列峰值与任务栈余量。
任务栈预算与内存监测；任务协作原创小课建设中。

阅读 FreeRTOS mutex 说明，理解基础优先级继承的适用边界；有互斥锁并不代表所有等待关系都安全。

06 /

调试与测试：能解释故障，才能证明修好了

先修
02—05；调试习惯贯穿全部阶段。
核心知识
学习断点、观察点、异常现场、反汇编、日志、单元与集成测试、回归定位。
贯穿项目
人为植入内存错误、竞态和异常协议输入。
验收证据
每个故障留下触发步骤、现场、根因、修复和回归测试。
HardFault 栈回溯分析 · EasyLogger 固件诊断

先链接寄存器、栈与异常模型，再按具体内核解释栈帧，参考 Arm Cortex-M7 文档。RTT 是观测手段，仍需测量日志开销；用 git bisect 定位一次已知回归。EasyLogger 同时适合练习并发、缓冲满、阻塞与性能。

07 /

启动与升级：失败后还能回到有效固件

先修
02、03、06：启动、协议与故障定位。
核心知识
学习 Flash 分区、镜像元数据、跳转、完整性、签名验证、版本策略和掉电恢复。
贯穿项目
先做本地串口升级，再扩展网络传输。
验收证据
篡改镜像被拒绝；在擦除、写入、提交阶段注入断电后可恢复；失败更新回退至允许的可信版本；禁止的旧版不能绕过版本策略。CRC 不替代签名。
MCU OTA：从分区到回滚

OTA 笔记是架构入口，后续将拆成多个原创小课，当前仍在建设中。笔记中的交互不是已完成升级实战的证明。方案选择参考 ST 安全启动与更新入口。安装断电恢复、试运行回滚和独立救援须分别验收。

08 /

架构与可靠性：把作品交给另一位工程师

先修
01—07。
核心知识
学习 BSP/分层、接口契约、故障状态机、持久化、看门狗、低功耗、自动构建和发布诊断。
贯穿项目
交付完整终端，并迁移一个板级实现验证接口边界。
验收证据
需求可追踪到测试；报告规定负载下的时序、丢包、资源和功耗；断电、断网与外设故障可重复；他人能按文档完成构建、烧录、升级和定位问题。保留设计取舍与未解决风险。
升级失败与恢复边界；可靠交付原创课程建设中。

贯穿项目在这里成为可维护交付：除了正常功能，还要描述失败行为、诊断入口和复现条件。工程协作工具可按需要使用，不是学习电路与外设的先修。

交叉核对的实际动作

每个主题建立一张小卡：问题与先修 → 三路资料的已知覆盖 → 芯片/工具差异 → 官方原理核验 → 原创实验 → 失败案例 → 证据与未决项。

例如队列主题先比较数据所有权和 ISR 边界，再在自己的工程重写采集流程，测试队列满和消费者变慢。记录何时入队失败、数据由谁释放，以及故障后系统还响应什么。

“安全 OTA、长时可靠性、自动化回归、量产诊断”等不能仅凭目录认定达标。它们是本站需要单独编写与验证的计划课程，并非断言任何资料系列没有讲。资料有公开入口不等于允许转载源码或教材，引用与复用许可应分别检查。

教学方法与公开边界

采用 Matt Pocock teach 的方法组织原创教学：每节 HTML 小课聚焦一个成果；另设可打印速查；先解释必要知识，再练习并立即反馈；用回忆、间隔复习和迁移题检验保持情况。若解释不清，可以继续向助手追问，再进入下一课。

每篇小课区分通用原理与实现案例；案例标明适用型号/版本，并包含先修链接、单一目标、白话解释、互动图、最小例子、误区、故障练习、验证方法、来源与下一课。未做硬件验证的例子明确标注；资料交叉核对用于定位差异与补缺。

公开内容只放原创讲解、原创例子、经审核的图示、实验和公开官方参考。私人课程入口、录播口令、付费源文件、个人作答与薄弱点不进入公开站；页面不显示个人掌握百分比。
