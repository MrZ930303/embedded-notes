GPIO 按键
电平、抖动与事件

一张可反复查阅的规则卡：先沿电路判断原始值，再用稳定状态的变化识别一次按下。

适用：STM32 / GD32 通用输入概念。先修：允许电源、共地。型号门限与库版本须按实际工程核对；人工示例未做硬件验证。

从输入到事件的四步

① 找电源与地② 判断 GPIO 电压区域③ 读原始逻辑值④ 稳定变化才发事件

打印会自动展开答案，打印结束后恢复原先展开状态。可在打印对话框选择纸张与页边距。

电路真值表：先把“按下”从 0/1 中拿开

电路与条件松开按钮可靠按下按下事件
上拉，按钮接地1 · 接近允许电源0 · 接近 GND稳定值 1→0
下拉，按钮接允许电源0 · 接近 GND1 · 接近允许电源稳定值 0→1
移除电阻，无其他驱动无法保证 · 悬空由按钮连接的电源或地决定先恢复可靠默认电平

逻辑 1 不是固定 1V。高低电平有效门限查完整料号的数据手册。悬空不等于必然随机翻转；上拉也不保证消除触点抖动。

连续稳定过滤

每 1 ms 采样；原始值改变就更新候选并重新计时。候选连续不变满阈值，才替换稳定值；只有稳定值变成有效电平才发一次按下事件。

if raw != candidate:
  candidate = raw; since = now
if candidate != stable
   and now - since >= threshold:
  stable = candidate
  if stable == 0: emit_pressed()

这里使用上拉低电平有效。示意未包含芯片驱动、计时回绕和并发；移植时分别处理。

人工例子：记时长，不数样点

初始 raw=stable=1。2/3/4/5/6 ms 依次变成 0/1/0/1/0，随后为 0 至 20 ms。

6 ms + 5 ms = 11 ms

原始下降沿：2、4、6 ms，共 3 个。5 ms 阈值：11 ms 确认 1 次按下。持续为 0 不重复计数。

拓展：24/25/26 ms 为 1/0/1；34/35/36 ms 为 0/1/0。默认阈值在31 ms确认释放，41 ms确认第二次按下；共2次。

所有时间均为人工教学数据，非硬件波形。5 ms 不是通用建议：阈值太短可能接纳抖动，太长增加延迟并忽略短状态。

上板验证清单

  1. 查板卡原理图、共地、完整料号、输入门限、允许电压、内部/外部上下拉与库版本。未知 5V 信号先停止接线。
  2. 测松开与按下的电压；用示波器或逻辑分析仪观察抖动。万用表不能证明短暂抖动不存在。
  3. 记录原始波形、采样周期、过滤阈值、稳定状态和事件计数。
  4. 测试按下保持、释放、第二次按下、短按；每个稳定按下只计一次，解释过滤延迟。
  5. 出现多计数时，对照原始边沿与稳定事件，保留触发条件、修复与回归证据。

回忆与迁移：先说理由，再看答案

不看上表，沿线路解释一次。稍后换个电路再问一遍，比当场顺口答对更能检验记忆。哪里不清楚，可以向助手追问线路、电平、采样与事件的具体差别。

上拉移除且按钮松开，读数为什么无法保证？

没有电阻和其他驱动提供确定电平，输入可能悬空。偶尔读到固定值不证明设计可靠；也不能声称它必然随机翻转。

改成下拉、按钮接允许电源，原始值与事件如何改变？

有下拉时松开为 0，按下为 1；稳定值 0→1 是按下事件。程序应把“原始值”和“业务按下”明确转换。

阈值改成 10 ms，人工例子何时确认？为何可能漏掉短状态？

最后变化发生在 6 ms，连续满 10 ms 是 16 ms。持续不足阈值的候选不会被接受；拓展中释放候选从 26 到 34 ms 仅有 8 ms，10 ms 阈值会把它忽略，因此没有第二次稳定按下。
