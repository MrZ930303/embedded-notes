固件诊断 / Cortex-M / FreeRTOS

EasyLogger：
从第一行日志到可维护的固件诊断

日志不只是“把字符发出去”。先决定哪些事件值得记录，再把格式、并发和传输分开管理。用四个能动手的实验，看清日志消失、阻塞和拥塞的原因。

适用：STM32 / GD32 的 Cortex-M、Keil MDK、FreeRTOS、J-Link。本文不涵盖 GD32 RISC-V 型号。

试一条日志查看移植清单先看验证边界

ONE LOG · THREE LAYERS

printf → 文本把参数格式化为字符
EasyLogger → 规则等级、标签、格式、过滤与共享缓冲
RTT / UART → 通道复制到 RAM 或排队发到串口

EasyLogger 可以使用 RTT。两者各管一层。

先记住这条最小路线

入门先采用同步 EasyLogger + FreeRTOS Mutex + RTT SKIP。正常任务调用 log_e / log_w / log_i / log_d，EasyLogger 管格式，项目的 elog_port_output 把文本交给 RTT。先不启用额外异步或缓冲模块，减少需要同时理解的状态。

这里“同步”表示调用任务完成格式化和向 RTT 复制；不表示 J-Link 已取走，也不表示 PC 已保存文件。普通日志接口只供正常任务调用。

由调度器启动后的初始化任务完成 AppLog_Init，再创建或放行会打印的业务任务。若需要上电早期记录，另做严格单写者的最小启动通道。ISR、故障处理和实时性要求严格的路径采用独立的有界事件记录。

临时看一个变量或很小的单任务程序，printf 可以够用；多模块、多人维护、要切换量产等级的固件，更适合统一日志入口。业务模块不直接绑定发送硬件，更换 RTT/UART 时主要调整移植层。

printf、日志策略与传输各管什么

printf 将参数按格式串变成文本，再交给 C 运行库输出。EasyLogger 在这之外提供等级、模块标签、统一格式和过滤。RTT 或 UART 则负责传输。换成 EasyLogger 并不会免去字符串格式化的 CPU、栈与 RAM 成本；浮点支持和体积还取决于工具链，库宣传的占用并非整个工程的占用。

源代码调用编译期宏筛选参数求值运行等级 / TAG共享缓冲格式化关键词筛选后端写入

关键词通常检查已经格式化的文本，不能当成完全免去格式化的前置开关。运行时不输出，也未必省去函数实参的求值。不要把业务行为写在日志参数里，例如 log_d("n=%u", ++counter)；编译关闭日志可能让这个自增也消失。

为什么参数求值值得单独强调

编译期宏可以把整次普通 log_x 调用删掉；保留下来的函数调用，参数表达式在进入函数前已经求值。因此先执行必要业务操作、保存结果，再记录结果。下面实验只增加虚拟计数，不执行用户输入的 C 表达式。RAW 与 hexdump 的路径另行审查。

来源：等级宏与接口 elog.h、格式化与过滤 elog.c。

开发常用 RTT，维修与工装按需 UART DMA

选择适合的场景需要接受的约束
J-Link RTT开发时通过调试接口访问 MCU RAM 缓冲，不额外占用 UART主机要消费缓冲；非阻塞也可能丢日志；部分目标只能使用会暂停 CPU 的 Stop Mode
UART DMA串口工装、产品测试、现场维修，不要求长期接 J-Link线路带宽有限；必须管理队列、DMA 缓冲寿命、错误与缓存一致性

RTT 常见背景访问不必为每个字符停 CPU，但不能承诺“完全不影响运行”。RTT、SWO/ITM 和半主机是不同机制；能看 SWO 的工具不代表支持 RTT。DMA 省去逐字节搬运的一部分 CPU 工作，格式化、复制、排队、启动、回调与缓存维护仍有成本。

两条通道都不是历史数据库。没有接收与持久化机制，旧日志通常无法事后找回。RTT 写入成功只说明进入 RAM；UART DMA 启动成功也不等于传输和记录已经完成。

RTT 三种满缓冲策略，先选 SKIP
  • SKIP：本次写入放不下就整次不写，不覆盖最旧消息；适合普通开发日志，同时统计未完整接收次数。
  • TRIM：尽量写入能容纳的部分，舍弃尾部。接收文本可能半行，UTF-8 也可能截在多字节字符中间。
  • BLOCK：等待空位。主机停止消费可能无限等待，不能放在必须持续运行的业务路径。

完整性单位是“一次写入”，不保证跨多次调用的长文本或 hexdump 完整。环形缓冲保留一个字节区分空与满，物理 2048 字节实际可用 2047 字节。“非阻塞”仅指 RTT 写入不等主机，整条日志仍可能有格式化、Mutex 等待和短临界区。

来源：SEGGER RTT 工作方式与模式、官方 RTT 源码。

Mutex、Assert 和 HardFault 是三件事

Mutex 是任务间轮流使用共享资源的“钥匙”。任务 A 持有日志锁，B 就等待；A 释放后 B 才使用同一缓冲。EasyLogger 的共享格式化缓冲要求锁覆盖格式化过程，不能只锁最后的 SEGGER_RTT_Write。直接绕过日志库写 RTT 的模块还要遵守 RTT 自身并发规则。

FreeRTOS 优先级继承可缓解部分优先级反转，但不能消除死锁，也不会自动保证固定最大等待时间。业务持有其他锁时再打印，可能形成循环锁依赖；严格时延任务应使用有界事件、汇总与限频。

普通日志不要用于 ISR、HardFault、栈溢出钩子、关中断临界区、调度器挂起区或日志自己的回调。时间戳、输出和断言处理回调不能再调用普通日志。

为什么“拿不到锁就直接返回”并不成立

elog_port_output_lock 返回 void。如果获取锁失败后从这个回调直接返回，日志核心仍可能继续改写共享缓冲，造成并发破坏。需要丢弃或有界等待时，必须在入口或架构层设计完整失败路径。初始化后保持格式与过滤稳定最易理解；运行修改同样需要同步。

仅判断 xTaskGetSchedulerState()==taskSCHEDULER_RUNNING 不代表当前不是 ISR：中断可以发生在调度器运行期间。ISR 不能获取或释放 Mutex，等待为零也不合法。xSemaphoreTakeFromISR/GiveFromISR 适用于相应二值/计数信号量，不能拿来操作 Mutex。

断言表达“必须成立”；可预期故障需要正常处理

Assert 用于检查资源创建成功、状态符合约定等程序员假设。队列满、设备断线通常是需要处理的业务故障。先执行操作、保存结果，再检查；不要把拿锁等副作用藏进 configASSERT，否则关闭断言可能连操作也删除。关闭断言后仍须有失败处理。

/* 教学顺序：先做操作，再检查结果；失败分支也须实现 */
result = CreateRequiredResource();
if (result == NULL) {
    IndependentFailurePath(); /* 不依赖日志锁的项目处理 */
    return;
}
configASSERT(result != NULL);

这些名称是伪代码，未提供对应板级实现。EasyLogger 默认断言处理可能再次打印，实际接入应换成独立路径。HardFault 是硬件异常，关闭软件断言不会修复非法访问、损坏的栈或错误上下文。开发期可停住调试，量产要有自己的安全处置与恢复策略。

来源：FreeRTOS 信号量与 Mutex 约束、FreeRTOS 调试与断言、EasyLogger 断言接口。

ISR 只记轻量事件，让任务解释

识别并处理中断源固定长度事件非等待投递任务取出并格式化

事件可包含 id、source、value，使用按值复制的短记录。不要把指向 ISR 局部变量的指针交给稍后执行的任务。队列在启用中断前创建，满时只统计丢失，不能等待；是否 portYIELD_FROM_ISR 按唤醒信息与具体端口规则处理。

高频 ISR 与 volatile 的边界

高频输入捕获或严格实时中断可只维护计数、标志或预分配环形缓冲。volatile 不等于原子性：多个 ISR 递增、任务读后清零、多字快照都须明确同步。微秒级时序用硬件捕获、周期计数或逻辑分析仪测量，不靠大量文本推断。

来源：FreeRTOS Cortex-M3/M4 中断优先级说明。

实验二：这个 IRQ 能调用 FromISR 吗

NVIC 数值越小越紧急；FreeRTOS 任务优先级数值越大越高。两者方向相反。即使 IRQ 落在允许范围，也只允许适用的 FromISR 接口，仍不能用 Mutex 或普通任务接口。

ISR 优先级检查器

教学模拟，不连接真实硬件。固定前提：典型 Cortex-M3/M4/M7 FreeRTOS 端口，所有实现位都用于抢占优先级。

P<T 更紧急，禁止所有 FreeRTOS API，包含 FromISR。寄存器阈值 = T << (8-b)。实际分组、器件实现位数与驱动参数编码必须核实，此处不生成通用初始化代码。

UART DMA 的关键：谁拥有这段内存

不能把 EasyLogger 的共享日志指针传给 HAL_UART_Transmit_DMA 后立即返回：DMA 还没读完，下一条日志可能覆盖那块内存。正确方向是复制到发送队列拥有的存储 → 单一发送者启动 DMA → 完成后才释放存储。

日志共享缓冲复制到队列槽位DMA 持有槽位完成 / 错误处理后释放
从教学流程到可用后端还缺什么
  • 定义复制入队接口、满队列策略、过长记录处理、多生产者同步和丢失计数。
  • 明确 BUSY、启动失败、完成及错误回调的存储归属，处理环形回绕；回调不能调用普通日志。
  • 确认 DMA 内存对外设可达，带 D-cache 器件按厂商要求清理缓存并对齐。
  • 停止或复位前的 flush 必须有时间上限。

打开 EasyLogger 异步宏不会自动解决这些问题。它通常仍先在调用方格式化，再决定哪些等级入缓冲，部分高严重度日志可能仍同步输出；异步也不自动代表 ISR 安全。

来源：EasyLogger 异步实现。DMA 可达性、缓存与 HAL 细节须查目标芯片及驱动文档。

实验三：RTT 空间满时发生了什么

环形缓冲是暂存区，不能无限蓄积。这里显式显示物理容量、保留字节、已用空间与读写指针。每次主机读取只消费当时已有字节，再让等待写入继续；模拟不尝试保存文本或还原被截断的字符。

RTT 环形缓冲实验

教学模拟，不连接真实硬件。输入按 TextEncoder 的 UTF-8 字节计数；实际固件编码由工程决定。

绿色为已用，斜线为保留的一个字节。大容量时按比例缩略；指针以数值为准。修改容量或模式会重建空缓冲；BLOCK 等待期间禁止同一发送者再次写入及改配置，可读取、断开、重连或重置。

重置会放弃等待写入；不是固件超时机制。BLOCK 无主机消费可一直等待。成功只表示写入 RAM；“主机已取走”也不等于文件已保存。

实验四：DMA 很快，线路装得下吗

8N1 每个有效字节在线路上占 10 位。115200 baud 的理论有效速率只有 11520 byte/s。启动 DMA 的 CPU 用时与整条数据的线路发送时间是两件事。

UART 带宽估算器

教学模拟，不连接真实硬件。固定 8N1 连续平均模型，忽略协议空闲、DMA 边界与调度开销。

图条以线路 100% 容量为上限；超过部分以数值与过载文字表示。

需求=B×f；理论速率=baud/10；单条线路时间=B×10000/baud 毫秒；占用率=需求/理论速率。持续超载时，近似填满时间=Q/(需求-理论速率)。平均可容纳仍可能因突发溢出。

HardFault 用独立通道保存最小现场

故障时任务栈、MSP、调度器和共享缓冲都可能已坏，处理入口不要依赖 log_e、FreeRTOS Mutex、动态内存或普通 Flash 驱动。先记录 EXC_RETURN、MSP/PSP 和可用故障寄存器，确认帧可读后才读取；保存到独立保留区，安全处置或复位，下次启动再验证解释。

异常帧不是“随便读 SP[6]”

Handler 中的 LR / EXC_RETURN 与异常帧内 LR 不同。对有效的原始 Cortex-M4 硬件帧，核心 PC 位于 SP+0x18；FP 扩展不会把核心帧移到 +0x48。不能无条件读取原始 SP[6]，是因为必须确认 SP 的含义、有效 RAM、对齐、整个帧可读性、地址加法溢出，以及入栈是否成功。FPU 扩展和延迟压栈仍需按内核规则检查。

STKERR / MSTKERR / LSPERR 等可能意味着现场不可靠；BFAR/MMFAR 结合有效位解释；非精确 BusFault 的 PC 不一定指向致错指令。M0/M0+ 不能套用完整 M4 故障寄存器模型。

即使待检 SP 合法，普通 C 处理函数自身也要有健康栈。MSP 已坏可能在检查前再次 fault。高可靠入口需要工具链与内核特定的最小汇编、独立紧急栈与反汇编审查；本文不提供假称跨 AC5/AC6 通用的处理器。

保留记录需要完整的提交与恢复协议

记录可包含 magic、版本、长度、固件构建 ID、序号、frame_valid、寄存器与校验。先标无效，写字段和校验，最后提交有效标记；启动验证后再使用。

保留 RAM 依赖正确段和 Scatter File 的 UNINIT 配置，启动程序、Bootloader、ECC 初始化与复位类型都不能覆盖它；NOINIT / UNINIT 不等于掉电保存。缓存与复位保持性必须实测。故障中写 Flash 要专门的失效设计，更稳妥的默认路线是可靠最小记录先保留，恢复后再持久化。

分析必须匹配当次构建的 AXF/ELF、Map、源码和编译选项，不能拿重新编译后的地址表猜测。

来源：ST PM0214 Cortex-M4 手册、Keil AN209 故障分析、Keil Scatter Loading。继续阅读站内HardFault 与异常栈帧笔记。

量产时保留重要事件，控制噪声与风险

构建建议策略
DEBUG保留常用等级；VERBOSE 临时打开并限频
TEST记录构建 ID、复位原因和关键事件，便于测试归因
RELEASE以 ERROR/WARN 为主，INFO 按需；编译关闭大量 DEBUG/VERBOSE

运行过滤无法恢复已编译删除的日志。RAW 和直接底层输出单独审查。日志不得包含密钥、密码、令牌或不必要个人数据；维修接口应有适当权限。

历史事件更适合有结构的二进制记录

重要历史可用固定长度记录保存事件 ID、时间基准、参数、次数、序号、构建 ID 和校验。做异常持续判定、恢复事件、限频、磨损控制和掉电恢复，不要每次循环都写 Flash。

看门狗重启后读取复位原因，应忠实写“上次复位原因为看门狗”，不要伪造一条复位前已经成功保存的事件。

人工硬件验收清单

以下是待执行的项目检查项，页面交互不会自动让它们通过。

  • 两个以上真实任务并发打印，检查行内容、锁范围与顺序。
  • 断开主机后业务仍运行，丢弃计数增长；验证 BLOCK 不会误用在关键路径。
  • 长行、浮点和峰值负载下测任务栈及最坏延迟。
  • 队列满不等待，核对真实 NVIC 优先级、分组及 FromISR 使用。
  • DMA BUSY、错误、回绕与缓存路径，槽位始终有明确所有者。
  • 安全环境中注入故障，核对复位保持、校验和匹配构建符号。
  • 审查量产字符串与敏感数据，归档对应符号文件和配置。

容易照抄错的地方

  • 本次核对的官方 ElogErrCode 只定义 ELOG_NO_ERR；不要照抄未定义的 ELOG_ERR。
  • 当前 RTT 接口名是 SEGGER_RTT_SetFlagsUpBuffer，不是 SEGGER_RTT_SetFlags；配置需对相关编译单元一致。
  • RTT 非阻塞不等于整条日志无等待，也不等于不丢日志。
  • 调度器运行不等于当前不是 ISR；异步日志不等于 ISR 安全。
  • DMA 指针必须活到传输完成，共享日志缓冲不能直接异步借出。
  • 断言是软件条件检查，HardFault 是硬件异常；两者不能混为一种错误处理。
  • 保留 RAM 不是掉电存储，故障 C 函数不能假设自己的栈健康。

四个实验只演示确定规则，不连接目标、不测硬件时序，也不证明板级接口可用。配置片段和伪代码仅用于解释，本页没有完整板级工程或参考代码下载。
