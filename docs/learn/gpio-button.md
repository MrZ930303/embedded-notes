# 按下按钮，为什么读到 0？ {#overview}

原创小课 01 · 电路与 C。只完成一件事：沿着线路解释原始电平，再把有抖动的输入变成一次可靠的“按下”事件。动作 → 电压 → 逻辑值 → 事件。

适用通用 GPIO 输入原理，不绑定开发板或固定引脚；需要会分辨允许电源与共地。交互模型与独立练习不依赖指定硬件，STM32/GD32 等芯片资料仅作实现案例；接入硬件后，型号门限和所用库版本须按实际工程核对。人工交互模型未做硬件验证，不连接真实设备。资料核对日期：2026-10-17。

本课属于[学习地图第 01 阶段](./engineering-map.html#stage-01)。另有[可打印速查](./gpio-button-reference.html)。

## 按下是动作，0 和 1 是电路的结果 {#core-idea}

手指按下是动作；引脚电压是物理量；程序读到的 0/1 是输入电路判定后的逻辑值。“按下”并不天然等于 1。逻辑 1 的有效电压范围由具体芯片的数据手册规定，不能把它理解成固定的 1 伏。

本课起点：GPIO 配为输入，一个电阻把引脚连向允许的 I/O 电源，按钮把同一输入连向 GND。这是“上拉电阻 + 按钮接地”的低电平有效电路。

- 松开且有上拉：电阻提供确定的高电平，原始值预期为 1。
- 按下并可靠接地：按钮把引脚拉低，原始值预期为 0；程序可把这个 0 解释成按下。
- 移除上拉且松开、没有其他驱动：输入可能悬空，原始值无法保证。悬空不代表必然随机翻转；偶尔读到固定值也不证明设计可靠。

内部上拉与外部电阻如何选择，要看实际板级设计和型号要求。输入模式、电气门限与允许电压参考 [ST AN4899](https://www.st.com.cn/resource/en/application_note/an4899-guidelines-for-gpio-hardware-settings-and-lowpower-consumption-on-stm32-mcus-stmicroelectronics.pdf)，具体门限仍需查完整料号的数据手册。

## 先预测，再改变线路 {#circuit-lab}

互动电路图提供下一次状态设置：上拉 / 下拉、接入 / 移除电阻、按下 / 松开按钮。先选择预测“应为 0、应为 1、不保证”，再提交预测并应用。图与读数始终对应已应用状态，只改设置不会提前揭晓答案。

反馈同时显示当前有效连接、原始值、预期电压区域和线路解释。上拉按下时形成允许电源 → 电阻 → GND 的支路电流，GPIO 节点由按钮接地。松开时无电源到地的闭合支路，本理想模型忽略微小输入漏电。移除电阻且松开时不绘制确定电流路径，不把悬空画成必然的随机翻转。

迁移练习：把电路改成下拉，电阻接地、按钮接允许的 I/O 电源。接入下拉且松开 → 0；按下并可靠接允许电源 → 1；移除电阻且松开、无其他驱动 → 无法保证。所有示意均为原创理想逻辑模型，省略输入保护等细节，不是实际接线指南。

## 一次动作，为什么出现三个下降沿？ {#bounce-lab}

机械触点可能短暂反复通断，一次按下形成多个电气边沿，这叫触点抖动。上拉解决悬空问题，不能保证消除抖动。原理参考 [TI：Debounce a Switch](https://www.ti.com/document-viewer/lit/html/scea094)。

时间轴采用人为构造的数据：初始 raw=1、stable=1；在 2、3、4、5、6 ms 依次变为 0、1、0、1、0，随后保持 0 到 20 ms。原始下降沿是 2、4、6 ms，共 3 个。每个下降沿都加一次会造成多计。

本练习每 1 ms 采样一次，候选值连续不变满 5 ms 才更新稳定值。每次原始值改变都重新计时。最后一次变为 0 是 6 ms，连续到 11 ms 满 5 ms，才产生一次稳定值 1→0 的按下事件。继续保持 0 不重复计数。

回放控件包括前进 1 ms、完整回放 / 暂停、查看完整结果、重置回放；显示当前时刻、raw / stable、原始下降沿、稳定按下事件、候选值起点和经过时长。曲线显示已回放部分，竖线表示当前采样时刻。

阈值可调为 1—12 的整数毫秒；空值、非有限值、非整数和越界输入拒绝运行，保留上一有效示例。更改阈值或拓展示例会重置回放。5 ms 是教学参数，不是所有按钮的通用建议；过短可能把抖动当事件，过长增加延迟并忽略短状态。真实参数需要测量。所有曲线和时间都是人工教学样例，非硬件波形。

拓展示例：24、25、26 ms 依次变为 1、0、1；34、35、36 ms 依次变为 0、1、0；保持至 50 ms。阈值 5 ms 时，31 ms 接受释放，41 ms 确认第二次按下，共 2 次稳定按下。原始下降沿共 6 个。阈值 12 ms 时，释放候选从 26 到 34 ms 只有 8 ms，不能被接受，因此不会产生第二次稳定按下。

## 把答案变成能解释的规则 {#lesson-notes}

完整笔记可展开、收起；深层链接自动展开对应内容；打印自动展开并在结束后恢复原先状态。

### 原始值、稳定值与事件，分别是什么？ {#raw-vs-event}

原始值是一次 GPIO 采样结果；稳定值是过滤器已经接受的状态；事件是稳定值从松开转成按下时的一次通知。上拉电路中稳定值 1→0 产生按下事件，此后持续为 0 不再通知。下拉电路的有效电平相应改成 1。

| 电路与条件 | 松开 | 可靠按下 | 稳定按下事件 |
| --- | --- | --- | --- |
| 上拉，按钮接地 | 1 | 0 | 1→0 |
| 下拉，按钮接允许电源 | 0 | 1 | 0→1 |
| 电阻移除，无其他驱动 | 无法保证 | 由按钮连接的地或电源决定 | 先恢复可靠默认电平 |

### 最小例子：连续稳定满 5 ms 才接受 {#filter-rule}

每 1 ms 采样。原始值一变，把它记作候选值，从当前时刻重新计时；候选连续保持满阈值才替换稳定值。

```text
初始：candidate = stable = 1，since = 0
每次采样 raw，当前时刻 now：
  如果 raw != candidate：
    candidate = raw
    since = now
  如果 candidate != stable 且 now - since >= threshold：
    stable = candidate
    如果 stable == 0：发出一次按下事件
```

时间来自单调计时；这里只是上拉低电平有效的算法示意，未包含具体芯片驱动、计时器回绕与并发处理。移植时分别处理。

候选 0 在 2、4 ms 开始后被打断；6 ms 再开始，11 ms 被接受。根据实际经过时长判断，不把五个采样点误当成已经经过 5 ms。

### 三个误区与一个故障练习 {#common-mistakes}

- “按钮按下就是 1”：先沿线路确定电平，再定义业务上的按下。
- “装了上拉就不用消抖”：上拉提供默认电平，触点仍可能反复通断。
- “悬空一定会随机跳”：悬空只表示无法保证有效值，偶然稳定不证明设计可靠。

故障练习：一次按下被计三次，先核对计数是否直接绑定原始下降沿；用人工数据重现，改为稳定值变化触发事件。上板再检查真实原始波形、采样周期与阈值，不能只凭“看起来好了”确认根因。

### 如何验收与上板验证 {#validation}

离线验收：解释三个上拉电路状态，数出 3 个原始下降沿，说明默认 11 ms 确认一次且持续不重复；加入释放和第二次按下确认 2 次；改变阈值解释延迟。

上板前查实际板卡原理图、完整芯片型号、GPIO 输入门限和允许电压，再确定引脚与上下拉。不要把未知 5V 信号接入 GPIO。型号与版本以实际数据手册、参考手册和所用库版本为准。

测量松开与按下的电压，用逻辑分析仪或示波器观察抖动。万用表不能证明短暂抖动不存在。记录采样周期、过滤参数、原始波形、稳定状态与事件计数；测试保持、释放、第二次按下、短按。此页面尚未完成这些硬件实测。

### 合上解释，再试三个问题 {#recall-questions}

1. 拿掉上拉，按钮松开且无其他驱动，为什么不能保证原始值？
2. 改成下拉、按钮接允许电源，松开和按下各读什么？业务按下事件识别哪个稳定边沿？
3. 同一人工输入把阈值改成 10 ms，何时确认第一次？更大阈值付出什么代价？

### 核对推理 {#recall-answers}

1. 输入没有确定的高或低驱动，读数不受设计保证。
2. 松开 0、按下 1，稳定值 0→1 作为按下事件。
3. 6 ms 后连续满 10 ms 是 16 ms，响应更晚，短状态可能被忽略。

稍后再不看答案解释一次，或换个电路推理。哪里说不清，可向助手追问，指出卡在电路、电平、采样还是事件。
