## 04 · byte连续性与饱和边界 {#tp-ref-loss-title}

<p>旧FIFO是4BYTE，FULL push先保持底层字段；UART上层明确清空queued4、清partial continuity，并丢失败第5byte。初始period100、旧command={SET_PERIOD,555}；receive A5 01 02 03均OK，尚未poll便没有新command。第5个A5返回UART_LOSS/FIFO_FULL/queuedBeforeLoss4/fullPreservedBeforeDiscard=true；losses1，period仍100。</p><p>poll1消耗0/events0/commandPresent=false，外部555保持。再给fresh A5 01 02 03，poll2消耗4/events4，才产生GET_STATUS/current100。这个已知例有5个入口byte不能进入后续解析，losses却只加一个<strong>事件</strong>；一般还可能有partial失效，不能推广成精确丢byte/packet数，也不承诺任意噪声最终重同步。</p><p>真实uart_poll仍先检查时间/20ms service-observed partial timeout，再最多drain4byte、5event、1command；每byte共享本轮now，无法还原wire interbyte time。MAX−1再加1到MAX且saturated=false；下一次尝试加才MAX/true。共享sticky标志不指出哪个counter截断，饱和诊断只能说明有限计数，不可算精确loss率。</p></section><section class="content-section" id="tp-ref-native">

## 05 · 真正组合、生命周期和work {#tp-ref-native-title}

<p>实际safe第四push仍WRITER/valid4/NDTR0；complete才READY/CT切换/NDTR4；begin另分配或LATE。2bank×4entry用actual(run,block,slot,index)关联fake source labels，成功push才commit。正常任一valid phase可claim READY，最多4实际read，copy值+matching label后release，再一次offer；queue不留lease/pointer。held-A是显式诊断策略。</p><p>N1实际读取A10..13、B20..23，B填充service0；两次complete/copy服务1与三次drain1给offered8/admit5/drop3/depart5/q0，2block/8copy/16Bpayload。N2held-A让begin LATE/no30write；未confirm recover BUSY，confirm但held也BUSY；matching release后recoverrun2丢READY1、长度0/NDTR4，start另一步block3；old token STALE。N3验证stopped READY可正常copy，实际UART状态在running/BOUNDARY/overloaded/两种stop仍可解析。</p><p>每turn≤1producer phase、1claim、4read、1release、1observe、2status、1queue step/4offers/4service、4sequence observations、5receive、1poll/4byte/5event/1command、1time_service/work1。每个component独立提交，拒绝只保持自身，不能回滚之前push/ingress/release。新queue/sequence C/H命名与完整output/lifetime合同在下载头文件，所有unused report槽确定置零，optional history32/row33drop不挡进度。fresh storage无old owner/events前提不能当可检查reset；所有real typed objects/output足够大、不重叠、exclusive/non-reentrant。README完整caller原文抽取，重复include/分编译link/normal与NDEBUG；host栈/.su不证明target/WCET/physical timing。</p></section><section class="content-section" id="tp-ref-recall">
